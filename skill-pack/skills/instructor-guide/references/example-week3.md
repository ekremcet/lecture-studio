# Week 3 Instructor Guide — Software Process Models

## Six 20-Minute Blocks

| Block | Core path | Student output |
|---|---|---|
| 1 | Process, process model, and four fundamental activities | Lifecycle artifact map |
| 2 | Specification, design/implementation, validation, evolution | Trace from requirement to validation evidence |
| 3 | Waterfall and V-model | Model recommendation for a regulated scenario |
| 4 | Incremental development and reuse-oriented engineering | Increment plan with integration risks |
| 5 | RUP, iteration, and hybrid approaches | Tailored hybrid process diagram |
| 6 | Comparative decision studio and project application | One-page process decision for D1 |

## Facilitation Notes

- Keep the discussion centred on constraints; no process model is universally “best”.
- In the model-selection activity, require one rejected alternative and its failure mode.
- The final studio output should be usable in the team's D1 submission.

## Minimum Viable Path

Fundamental activities → Waterfall/V-model → incremental/reuse → process-selection studio.

## Extension

Introduce a surprise requirement after teams select a process and ask how their plan absorbs the change.
